# Contributing

This project welcomes criticism, alternative formulations, real-world cases and policy corrections. It is not a campaign to maximise AI use or require researchers to describe machines in one philosophical vocabulary.

Start with the [working principles](docs/principles.md) and [decision log](provenance/decision-log.md). Propose a small, coherent change. Explain the problem it addresses, whether it changes an established direction or an unendorsed draft, and any trade-offs. A useful contribution can be an issue, an example, a source correction or an edited paragraph; code is not required.

## Evidence and examples

Support factual claims about policies or scholarship with primary sources and a date of inspection. Give the actual scope of your check and note uncertainty. Do not copy whole publisher pages into the repository by default. Keep short quotations within appropriate limits and preserve third-party rights.

Use real declarations only with suitable permission and attribution. Remove confidential material and unnecessary personal details. Label synthetic or composite examples clearly; never allow them to be mistaken for records of completed validation.

## AI participation in contributions

AI-supported and collaboratively developed contributions are welcome. Briefly describe substantive AI involvement in the pull request when relevant, without assigning token percentages or fabricating task boundaries. The person submitting the contribution is responsible for reviewing it and respecting others' rights.

## Review and changes

The proposed initial maintainer is Barry W. Brook; see [governance](GOVERNANCE.md). A disagreement with a founding assumption is welcome when made explicit. Do not quietly change the default to rigid roles, turn speculative forecasts into factual claims or convert unresolved proposals into settled principles.

For code changes, run the checker and unit tests documented in [START_HERE.md](START_HERE.md). For prose changes, check consistency, links, source support and any resulting changes to templates. Record material changes in [CHANGELOG.md](CHANGELOG.md).

## Licensing

Contributions should be offered under the applicable directory licence described in [LICENSE.md](LICENSE.md), with any third-party restrictions identified. The scaffold's licence choices are pending maintainer review before first publication. Do not import incompatible material on the assumption that public availability means unrestricted reuse.

## Conduct

Critique ideas and evidence, not the worth of contributors. Do not harass, impersonate, expose personal information or use issues to publish confidential allegations. Keep participation accessible to people with different expertise, disciplines and views about AI. Maintainers may moderate contributions to protect that environment; governance beyond the initial draft is open for development.
